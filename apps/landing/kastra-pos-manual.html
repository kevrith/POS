Chapter 1

Introduction

KASTRA POS is Kenya's most comprehensive enterprise Point of Sale platform — purpose-built for KRA eTIMS compliance, offline-first resilience, and multi-store scalability.

1.1 About KASTRA POS

KASTRA POS is an enterprise-grade, offline-first Point of Sale system designed specifically for Kenyan businesses of all sizes — from single-location cafés to multi-branch franchise chains. The system covers every aspect of business operations: from ringing up a sale and printing a KRA-compliant receipt, to running payroll, managing hotel rooms, analysing AI-driven demand forecasts, and syncing with QuickBooks.

Chapter 4

Installation Guide

Full production installation on Ubuntu 22.04 LTS. Estimated time: 45–60 minutes.

4.1 Pre-Installation Checklist

  • ☐ Server with Ubuntu 22.04 LTS (root/sudo access)
  • ☐ Domain name pointed to server IP (e.g., pos.yourbusiness.co.ke, api.yourbusiness.co.ke)
  • ☐ SSL certificate ready (Let's Encrypt recommended)
  • ☐ KRA eTIMS credentials (Branch ID, TIN, CMC Key) — optional at install time
  • ☐ M-Pesa Daraja API credentials — optional at install time
  • ☐ Resend API key for email notifications — optional

4.2 Server Setup

# 1. Update system
sudo apt update && sudo apt upgrade -y
sudo apt install -y curl wget git build-essential

# 2. Install Node.js 20
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs
node --version  # Should show v20.x.x
npm install -g pnpm pm2

# 3. Install PostgreSQL 14
sudo apt install -y postgresql postgresql-contrib
sudo systemctl start postgresql && sudo systemctl enable postgresql
sudo -u postgres psql <<EOF
CREATE DATABASE kastra_pos;
CREATE USER kastra WITH ENCRYPTED PASSWORD 'your_secure_password';
GRANT ALL PRIVILEGES ON DATABASE kastra_pos TO kastra;
\q
EOF

# 4. Install Redis (optional — enables job queues)
sudo apt install -y redis-server
sudo systemctl start redis-server && sudo systemctl enable redis-server
redis-cli ping  # Should return PONG

# 5. Install Nginx
sudo apt install -y nginx

4.3 Application Installation

# Create app directory
sudo mkdir -p /opt/kastra-pos
sudo chown $USER:$USER /opt/kastra-pos
cd /opt/kastra-pos

# Clone repository
git clone https://github.com/your-org/kastra-pos.git .

# Install all dependencies (monorepo)
npm install

# Configure environment
cp apps/api/.env.example apps/api/.env

4.4 Nginx Configuration

sudo nano /etc/nginx/sites-available/kastra-pos
# API Server
server {
    listen 80;
    server_name api.yourbusiness.co.ke;
    location / {
        proxy_pass http://localhost:3010;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_cache_bypass $http_upgrade;
    }
}
# Web POS App
server {
    listen 80;
    server_name pos.yourbusiness.co.ke;
    root /opt/kastra-pos/apps/web/dist;
    index index.html;
    location / { try_files $uri $uri/ /index.html; }
    location /api { proxy_pass http://localhost:3010; }
}
# Admin Panel
server {
    listen 80;
    server_name admin.yourbusiness.co.ke;
    root /opt/kastra-pos/apps/admin/dist;
    index index.html;
    location / { try_files $uri $uri/ /index.html; }
}
# Enable and test
sudo ln -s /etc/nginx/sites-available/kastra-pos /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl restart nginx

# Install SSL (Let's Encrypt)
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d api.yourbusiness.co.ke -d pos.yourbusiness.co.ke -d admin.yourbusiness.co.ke

# Firewall
sudo ufw enable
sudo ufw allow 22/tcp && sudo ufw allow 80/tcp && sudo ufw allow 443/tcp

# Verify
curl https://api.yourbusiness.co.ke/api/v1/health
# Should return: {"status":"ok"}

Initial Setup Wizard

When you first access KASTRA POS, a multi-step wizard guides you through essential configuration.

1
Welcome Screen

Overview of the setup process. Click Get Started to begin.

2
Business Profile

Business Name (as registered with KRA) · Business Type (Retail / Restaurant / Supermarket / Pharmacy / Hotel / Salon / Clinic) — determines which modules appear in navigation · Tax Type: VAT 16% (turnover > KES 5M/year) or TOT 3% (turnover < KES 5M/year) · Phone, email, address, currency.

3

Store Name (e.g., "Main Branch – Nairobi CBD") · Store Code (max 10 chars, e.g., "NRB01") — used in receipt numbers: NRB01-2026-0000001. Click Create Store.

4
KRA eTIMS (Optional)

Branch ID (BHF ID): Usually "00" for single location · TIN: Your KRA PIN in P000000000A format · CMC Key: From KRA iTax portal. Click Save & Test Connection. Skip if credentials not yet available.

5
Ready to Sell

System is configured. Recommended next steps: Add Products → Add Staff → Configure Printers → Start Selling. Click Go to POS.

💡
Tip

All wizard settings can be changed later in Settings. You don't need eTIMS credentials to start selling — submit sales manually in bulk when you're ready.

Chapter 7

Point of Sale Operations

The POS screen is the heart of KASTRA. It handles retail checkout, restaurant orders, barcode scanning, promotions, loyalty points, and eTIMS submission — all in one interface.

7.1 POS Screen Layout

7.2 Adding Items to Cart

Method 1 — Click Product Tile

Browse the item grid, click any product card. Item is instantly added to cart with quantity 1. Click again to increment.

Method 2 — Barcode Scanner

Focus the search bar (click it or press F2). Scan barcode with USB/Bluetooth scanner. Item is found and added automatically. If barcode matches multiple items, a dropdown appears.

Method 3 — Camera Barcode (mobile/tablet)

Click the camera icon next to the search bar. Grant camera permission. Point camera at barcode — ZXing decodes it and adds the item.

Method 4 — Quick Keyboard Entry (Power Users)

Type a quantity-multiplier expression in the search bar and press Enter. Example: 3×500 or 3*500 — adds 3 units of the item priced at KES 500. For barcode: 5×6001020003004 adds 5 units of that barcode.

7.3 Price Levels

At the top of the search bar, three pill buttons switch the pricing mode applied to all items in cart:

  • Retail — Standard retailPriceCents (default)
  • Wholesale — wholesalePriceCents (requires item to have wholesale price set)
  • VIP — vipPriceCents (requires item to have VIP price set)
ℹ️
Note

Price level applies to all items. For per-item price override, use the edit (pencil) icon on the cart item row — requires Manager PIN if cashier role.

7.4 Special Sale Types

Layaway (Instalment Plan)

  1. Add items to cart, click Layaway button
  2. Select/create customer (required)
  3. Enter: initial deposit · payment schedule · due date
  4. Click Create Layaway — stock is reserved
  5. Manage via Reports → Layaway Book. Add payments via "Add Payment" button. Converts to sale on full payment.

Proforma Invoice

  1. Add items to cart, click Proforma button
  2. Enter customer name, valid-until date, notes
  3. Click Generate Proforma — no stock deduction
  4. Convert: Reports → Proforma Pipeline → find proforma → click Convert to Sale → process payment

Credit Sale

  1. Add items, select customer (required — must have credit limit set)
  2. In payment modal, select Credit
  3. System verifies credit limit. Sale completes; amount added to customer's outstanding balance.
  4. Record payment: Customers page → select customer → Add Payment

7.5 Voiding Sales

⚠️
Requires Manager or Owner

Cashiers cannot void sales. A PIN challenge appears for Manager-level authorization.

1
Navigate to Sales History

Find the sale to void. Sales must have PAID status.

2
Click Void

Select void type: Full Void (cancel entire sale) or Line Item Void (cancel specific items). Enter reason.

3
Confirm

Enter Manager PIN. Effects: stock returned · payment refunded (cash or credit note) · void record created for audit · eTIMS void notification sent to KRA.

7.6 FEFO & Expiry Warnings

When a batch-tracked item is added to cart, the system checks expiry dates:

  • EXPIRED — Sale blocked. Item cannot be sold.
  • CRITICAL — Expires within 7 days. Warning modal shown; cashier can proceed or remove item.
  • WARNING — Expires within 30 days. FEFO suggestion banner shows recommended batch.

FEFO (First Expired, First Out) — The system always deducts from the batch with the nearest expiry date first.

Chapter 8

Payment Methods

8.1 Cash

Enter the amount tendered. System automatically calculates change. Click Complete Sale. Cash drawer triggers automatically.

8.2 M-Pesa STK Push

1
Enter Phone Number

Type customer's Safaricom number (07XX or 2547XX format). System sends STK push prompt to customer's phone.

2
Customer Approves

Customer enters M-Pesa PIN on their phone. System polls Daraja API every 3 seconds for up to 2 minutes.

3
Auto-Confirm

On success, payment auto-confirms and sale completes. M-Pesa transaction code is recorded. On timeout, cashier can enter code manually via "Add Payment" flow.

8.3 M-Pesa Dynamic QR

Click M-Pesa QR. System generates a Daraja QR code displayed on screen. Customer scans with M-Pesa app and pays. System auto-confirms via webhook. Ideal for counter/restaurant setups where customers self-pay.

8.4 Card / Paystack

Click Card. System initiates Paystack payment. Customer taps/swipes card on terminal. Enter approval code when prompted. Click Complete Sale.

ℹ️
Setup

Requires Paystack credentials in Settings → Payments → Card. Contact Paystack Kenya (+254) to obtain credentials.

8.5 Bank Transfer

Select Bank Transfer. Enter reference number (from customer's bank receipt or confirmation SMS). Sale records the reference for later bank reconciliation matching.

8.6 Credit / Account

Customer must be selected with a credit limit set. Remaining credit is shown. Sale is marked CREDIT; amount added to customer outstanding balance. View and record payments via Customers → Credit Management.

8.7 Split Payment

Click Split Payment. Add multiple payment rows — any combination of methods. Example: KES 1,000 Cash + KES 2,000 M-Pesa. The total must equal the cart total. Click Complete Sale when all splits balance.

8.8 Gift Card

In the payment modal, click Gift Card tab. Scan barcode or enter gift card code. System validates balance and applies it. Remaining balance usable in future sales.

💡
Tip

Create and manage gift cards via Sales → Gift Cards page. Set denomination, expiry date, and optional customer assignment.

8.9 Loyalty Points Redemption

When a customer is selected and has loyalty points, a balance chip appears in the cart header. Toggle Redeem Points to convert points to a KES discount. The redemption rate is set in Settings → Loyalty Program.

8.10 Room Charge (Hotel Mode)

Available when Hotel module is active. Select the guest's room number. Amount is posted to the guest's folio. Settled at checkout. Requires hotel integration to be configured.

9.3 Batch & Expiry Tracking

For pharmacy, food, or any perishable items:

1
Enable on Item

Edit item → check Track Batches and Track Expiry → set Default Expiry Days → Save.

2
Receive Batch

When creating a GRN for this item, enter: Lot/Batch number, Manufacturing Date, Expiry Date, Quantity received. Each batch is tracked separately.

3
FEFO at POS

When selling, the system automatically deducts from the batch with the nearest expiry date first (First Expired, First Out).

4
Batch Recall

Inventory → Batch Management → find batch → click Recall. Marks all units as recalled. Sends notification to all affected stores. Recall note required.

9.4 Serial Number Tracking

For electronics, high-value items, and warranty tracking:

  • Edit item → check Track Serial Numbers
  • Add serials: Inventory → Serial Tracking → + Add Serial (or bulk import CSV)
  • At POS, when item is added to cart, system prompts: "Select Serial Number"
  • Serial marked as SOLD; linked to customer and sale
  • View: Reports → Serial Registry (filter by status: Available / Sold / Reserved)

9.5 Recipe / BOM Management

For restaurants and manufacturers — define finished products in terms of ingredients:

  1. Inventory → Recipes/BOM → + New Recipe
  2. Enter: Recipe Name, Selling Price, Yield (portions per batch)
  3. Add ingredients: select item, enter quantity (grams/units per portion)
  4. System calculates: Total Cost, Cost per Portion, Profit Margin
  5. When recipe item is sold at POS, ingredients are automatically deducted

Recipe Variance Report: Reports → Recipe Variance — compares planned vs actual ingredient usage. Identifies waste, over-portioning, or theft.

9.6 Stocktake / Physical Count

  1. Inventory → Stocktake → New Stocktake Session
  2. Select store and date. System generates counting sheets.
  3. Count physical stock. Enter actual counts per item.
  4. System calculates variance (System vs Actual). Review discrepancies.
  5. Click Finalise Stocktake — stock adjustments are created automatically for variances.
⚠️
Best Practice

Conduct stocktakes at end of day (after Z-Report) to avoid counting discrepancies from in-flight sales.

9.7 Barcode Label Printing

Inventory → Items → select items → click Print Labels. Choose label format (58mm or 80mm roll). Labels include: item name, barcode, price. Requires a label printer with routing handle LABELS configured in Settings → Printers.

9.8 Prescription Management (Pharmacy)

The Prescriptions module is available when your Business Type is set to Pharmacy or Clinic. Navigate to Inventory → Prescriptions to access the prescription queue.

9.8.1 Prescription Statuses

StatusBadge ColourMeaning
PENDINGYellowPrescription received, awaiting dispensing or action.
DISPENSEDGreenAll items dispensed; stock deducted; prescription complete.
PARTIALLY_DISPENSEDBlueSome items dispensed; remaining items still outstanding.

9.8.2 Prescription Queue Filters

The prescription queue provides filter tabs at the top of the screen so staff can quickly locate prescriptions by status:

  • All — shows every prescription regardless of status.
  • PENDING — prescriptions awaiting action (the default working view).
  • DISPENSED — completed prescriptions for record-keeping.
  • PARTIALLY_DISPENSED — prescriptions where dispensing is still in progress.
  • REFERRED_EXTERNAL — prescriptions referred to an outside pharmacy.
  • CANCELLED — voided prescriptions.

9.8.3 Dispensing a Prescription

1
Open Prescription

In the prescription queue, click on a PENDING prescription to open the detail view.

2
Review Items

Confirm each drug on the prescription, verify available batch stock and expiry dates. The system applies FEFO — the batch nearest to expiry is selected first.

3
Dispense

Click Dispense. Stock is deducted from inventory and the prescription status changes to DISPENSED (or PARTIALLY_DISPENSED if any items could not be fulfilled).

4
Attach to Sale

If payment is required at the counter, the dispensed items can be added directly to a POS cart for checkout, creating a linked sale.

9.8.4 Referring a Prescription Externally (Refer Out)

Use the Refer Out action when one or more required drugs are not in stock and the patient needs to obtain them from a different pharmacy. No stock is deducted when a prescription is referred out.

1
Open the Prescription

In the prescription queue, click on a PENDING prescription to open its detail view.

2
Click "Refer Out"

Click the Refer Out button. A modal dialog will appear prompting for referral details.

3
Enter Referral Notes

In the notes field, record the reason for the referral and the name of the external pharmacy or facility the patient is being directed to (e.g. "Haltons Pharmacy, Westlands — Amoxicillin 500mg out of stock"). This field is mandatory.

4
Confirm

Click Confirm Referral. The prescription status immediately changes to REFERRED_EXTERNAL and no inventory adjustment is made.

💡
Tip

Referred prescriptions are visible in the REFERRED_EXTERNAL filter tab. The referral notes you entered are displayed in a purple "Referred Out" card inside the prescription detail view, providing a permanent audit trail.

Important

17.2 Configuration

Chapter 19

Security & Access Control

19.1 Authentication Methods

  • Email + Password: Standard login. bcrypt-hashed. Minimum 8 characters enforced.
  • PIN Login: 4–6 digit PIN for quick POS access. 15-minute PIN session (shorter than full JWT session).
  • Google OAuth: Staff can sign in with Google accounts linked to their user profile.
  • TOTP 2FA: Settings → Security → Enable Two-Factor Authentication. Scan QR code with Google Authenticator. Required on every login once enabled.

19.2 Login Lockout

After 5 consecutive failed login attempts, the account is locked for 15 minutes. The owner receives a security notification. Lockout can be cleared manually by an Owner from Settings → Users.

19.3 Auto-Lock / Inactivity Timer

Settings → General → Inactivity Timeout. After N minutes of inactivity, POS locks with PIN prompt. Enter staff PIN to unlock without full re-login. Configurable per business (default: 10 minutes).

19.4 API Keys

Settings → API Keys → + Generate API Key. The raw key is shown once — copy immediately. SHA-256 hash is stored in database. Keys can be revoked without regeneration.

  • IP Whitelist: Optionally restrict API key to specific IP addresses
  • Scope: Keys have read-only or read-write scope
  • Used for third-party integrations (webhook consumers, accounting systems, etc.)

19.5 Encryption

All sensitive credentials (M-Pesa keys, eTIMS CMC Key, Africa's Talking credentials, accounting tokens) are stored encrypted using AES-256-CBC with a random IV per encryption. The ENCRYPTION_KEY environment variable is the master key.

🔒
Key Rotation

If the encryption key is compromised, rotate it via: POST /api/v1/super-admin/rotate-encryption-key with body {"oldKey":"...","newKey":"..."}. This re-encrypts all stored credentials in a transaction. Run immediately if key compromise is suspected.

19.6 Audit Trail

Every action in the system is logged: who did what, when, from which IP. Audit logs are tamper-evident and cannot be edited. Export via Reports → Audit Log Export (CSV or JSON).

19.7 Security Headers

The API uses Helmet.js to set: HSTS, X-Frame-Options, X-Content-Type-Options, Content-Security-Policy, and X-XSS-Protection headers on all responses.

23.1 Common Issues

SymptomLikely CauseSolution
Cannot login — "Invalid credentials"Wrong password, caps lock on, or locked accountCheck caps lock. Try password reset. If locked (5 failures), wait 15 min or ask Owner to clear lockout.
Barcode scan doesn't add itemScanner not in keyboard wedge mode; barcode not in systemTest scanner in Notepad — it should type characters. Enable keyboard wedge mode + Enter suffix. Check item has barcode set in inventory.
Receipt not printingPrinter offline or wrong portCheck power/paper. Verify USB/Network connection. Settings → Printers → Test Print. Reinstall printer driver if needed.
M-Pesa STK push not receivedWrong phone number format; Daraja sandboxVerify Safaricom number. Check MPESA_ENV=production in .env. Confirm M-Pesa credentials are live, not sandbox.
eTIMS submission failedTIN format wrong, branch not registered, API timeoutVerify TIN format (P000000000A). Check BHF ID. Try manual batch submission. Review error message in Settings → KRA eTIMS.
Stock not updating after saleItem "Track Stock" not enabled; sync issueEdit item → confirm Track Stock is checked. Check Inventory → Movements log for the item. Refresh page (F5).
Page loads slowlyLarge database, poor connection, browser cacheClear browser cache. Close unused tabs. Check internet speed. Consider server upgrade if consistent.
POS reloads to login on every API error401 loop — expired sessionClear sessionStorage (DevTools → Application → Session Storage → clear). Re-login. The pos-auth key is automatically cleared on 401.

25.1 Glossary

TermDefinition

KDSKitchen Display System. Screen in kitchen showing live order queue.

NHIFNational Hospital Insurance Fund. Mandatory health insurance deduction.

POPurchase Order. Formal order document sent to a supplier.

Recipe/BOMBill of Materials. Defines ingredient quantities needed to produce one unit of a finished item.
